Concept 8: ACID Transactions & Concurrency Control Transactional Integrity
Atomic Seat Reservation Workflow (BEGIN → COMMIT / ROLLBACK)

Demonstrates row-level locking (FOR UPDATE), duplicate seat prevention, atomic booking creation, payment insertion, and rollback on constraint violation.

-- Step 1: Initialize atomic boundary
START TRANSACTION;

-- Step 2: Lock candidate trip and evaluate status
SELECT trip_id, bus_id, trip_status FROM trips WHERE trip_id = ? FOR UPDATE;

-- Step 3: Verify requested seat is not already confirmed
SELECT booking_id FROM bookings WHERE trip_id = ? AND seat_id = ? AND booking_status = 'CONFIRMED' FOR UPDATE;

-- Step 4: Insert booking tuple
INSERT INTO bookings (booking_reference, trip_id, passenger_id, seat_id, booking_time, booking_status, total_amount)
VALUES (?, ?, ?, ?, NOW(), 'CONFIRMED', ?);

-- Step 5: Insert payment tuple linked 1:1
INSERT INTO payments (booking_id, amount, payment_method, payment_status, payment_time, transaction_reference)
VALUES (LAST_INSERT_ID(), ?, ?, 'PAID', NOW(), ?);

-- Step 6: Atomic commit (If any check fails, Python issues ROLLBACK)
COMMIT;
